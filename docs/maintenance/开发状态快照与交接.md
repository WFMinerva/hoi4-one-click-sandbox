## 5. 踩坑经验（通用条款，跨工具链）

1. **`Expand-Archive` 解压嵌套**：将 ZIP 解压到已存在的同名目录会得到 `根/子目录/内容` 的双层嵌套；启动器按 `.mod` 的 `path` 找 `descriptor.mod` 时会扑空 → MOD 未加载、无决议。正确做法：先删除旧目录，再解压到 `mod` 根目录，并立即用目录列表核对 `descriptor.mod` 层级。
2. **`.mod` 文件 `path`**：仓库约定 `path="mod/OCS_one_click_sandbox_start_v2_0"`，内容目录必须与该相对路径匹配（`mod/OCS_one_click_sandbox_start_v2_0/descriptor.mod`）。启动器层面 `dlc_load.json` 会记录启用状态。
3. **启动器缓存**：`Documents\Paradox Interactive\Hearts of Iron IV\` 下的 `dlc_load.json` / `launcher-v2.sqlite` 记录 MOD 启用与注册；反复删除/重建 MOD 目录后若启动器不识别，可清理相关缓存后重开启动器。
4. **日志读取注意事项**：
   - 编辑器占用日志文件通常不影响读取（共享读锁），但游戏启动时若文件被独占占用可能写不进去，进游戏前建议关闭日志查看窗口。
   - `read_file` / `search_files` 可能返回**缓存旧内容**；判断"最新一轮"要看日志文件时间戳，而不是依赖对话中的历史读取结果。必要时应改用 `python` 直读文件系统绕过缓存。
   - `error.log` 顶部 6 行 `gamelobby.cpp` / `remotefile.cpp` 的 `Failed allocate data buffer` 是游戏本体网络模块噪音，**与本 MOD 无关**，无 MOD 时也会出现。
5. **PowerShell 转义**：默认终端为 PowerShell；`&&` 不是有效语句分隔符（用 `;`），`grep` 命令不存在（用 `findstr`），`$_` / 中文引号在命令行粘贴时会丢字符或报参数空，复杂命令建议写成独立的 `.ps1` 或避免内联。
6. **steamcmd 交互登录**：steamcmd 是交互式控制台程序，AI 执行环境的键盘输入无法实时转发（会读空密码导致 Invalid Password）。正确做法：先跑 `python tools/publish_workshop.py --steamcmd D:\steamcmd\steamcmd.exe --prepare-only` 生成 VDF 与暂存目录，再用 `cmd /c start "OCS Workshop Upload" cmd /K "D:\steamcmd\steamcmd.exe +login <账号> +workshop_build_item D:\steamcmd\hoi4_ocs_workshop.vdf +quit"` 弹出独立窗口，由维护者在该窗口输入密码（**输入不回显属正常**）与 Steam Guard；上传成功从 `D:\steamcmd\logs\workshop_log.txt` 判读 `Upload finished for workshop item 3767025052 : OK` 与 `ManifestID xxx`，再把 Manifest 同步到 AGENTS.md 与 docs。**注意：`+login` 后必须带账号名，否则 steamcmd 直接打印 `Usage: login <username>` 退出**。
7. **工坊简介 VDF 解析与长度**：VDF 的 `description` 若含 ASCII 双引号会提前闭合字符串（报 `got } in key` / `AddStringToPool: key name too long`）；工坊简介文本内的引号应统一用弯引号（与中文段一致）。上传提交阶段若报 `Committing update...ERROR! Failed to update workshop item (Invalid Parameter)`，优先压缩英文简介长度（v2.6 中文 2209 + 英文 2595、合计 4832 字符可通过）；预览图控制在 1MB 内。
8. **steamcmd 路径**：`F:\steamcmd` 是家用机（Codex 维护环境）写入的真实路径；单位机本次安装在 `D:\steamcmd`。两者都是实际路径，按当前机器选用并传给 `publish_workshop.py` 的 `--steamcmd` 参数（该参数天然支持任意盘符）。
9. **仓库根目录**：单位机与家用机的项目地址可以不同，任何脚本都不得写死仓库绝对路径；应从脚本自身位置推导仓库根目录。游戏、Paradox用户目录与steamcmd路径通过参数、`HOI4_VANILLA_PATH`或当前机器自动探测处理。
10. **Steam 客户端订阅缓存**：工坊上传成功后，已登录的 Steam 客户端不一定立即拉取新内容——它可能继续持有旧 manifest 的本地订阅缓存（表现为订阅目录 `steamapps\workshop\content\394360\3767025052\descriptor.mod` 仍为旧版本、进 MOD 仍是旧内容）。此时**不是上传失败**：退出 Steam 客户端后重新登录（或取消订阅再重新订阅）即会拉取新文件。判定上传结果必须看 `D:\steamcmd\logs\workshop_log.txt` 的 `Upload finished ... : OK` 与 ManifestID，以及 Steam API `GetPublishedFileDetails` 的 `time_updated`，而不是看客户端本地缓存。v2.6 实盘：`Upload finished ... OK`（manifest `3609146315690391433`）后客户端缓存仍显示 v2.5，重订阅后变 v2.6 且实机通过。
11. **发布包换行与跨机器复现**：v2.6 官方附件来自单位机混合 LF/CRLF 工作区；官方 SHA-256 `484030065363ab1366604d17e2f92ee114208b2edb7ffe13b001a0172de48ff1` 在该工作区两次一致，但干净标签检出不能字节级复现。统一换行后所有差异文本内容一致。当前 `build_release.py` 与工坊暂存会统一文本为 LF、保留本地化 BOM；v2.6 规范化审计重建 SHA-256 为 `9b4cc601ca9c82e59541665a076f16c972dab9c18d6871677f4887e2df1e7467`。
