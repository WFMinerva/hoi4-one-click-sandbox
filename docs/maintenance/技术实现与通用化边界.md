## 一、总体架构

v2.0采用“通用核心＋PRC增强层”。脚本文件仍沿用`PRC_OCS_`前缀，这是稳定键名，不代表功能仍仅限PRC。不得为了美观批量重命名这些键，否则可能破坏存档标志、事件和本地化引用。

## 二、国家识别

通用入口面向所有`is_ai = no`国家。PRC增强层使用`tag = PRC`与`original_tag = PRC`识别，确保PRC改国号或形成动态身份后仍保留专属效果，同时避免其他中国国家误获PRC内容。

## 三、科技

科技效果继续使用明确列出的原版科技键，实机效果按用户判断等同控制台`research all`。主要国家科技树外观可能不同，但不另做逐国科技分支。

## 四、装备和模板

- PRC与非PRC分别创建中国名称和中性名称的22个设计。
- 通用设计不得引用PRC专属`design_team`。
- PRC的“主力纯步师”“卫戍部队”“主力步坦师”保留民兵营。
- 非PRC三个对应模板将民兵营全部替换为普通步兵营，共42处。
- 初始化只创建模板，不自动改编现役部队。
- 独立改编决议将全军改成同名“卫戍部队”，模板会按国家分支解析。
- 基础 PRC“装甲师”当前为8个 `mechanized`＋10个 `medium_sp_artillery_brigade`；维护者接受其作为 v2.2-test1 限制，后续版本改为10＋8。二阶段“装甲师·进化型”是独立模板，仍为12＋6，不得混改。

## 五、24师增援

v2.2-test1 起改为可重复决议：仅在初始化后显示，选择本国拥有且控制的一个州，一次创建24个同名“主力纯步师”。每个师设置100%人力、装备和初始训练度；完成后等待1天即可再次执行。此变更尚待实机验证，v2.1稳定基准仍为一次性语义。

## 六、建设作用域

所有通用建设使用`every_owned_state`并在单一`limit`块内检查`is_controlled_by = ROOT`。沿海船坞同时在同一个`limit`块中检查`is_coastal = yes`。禁止重新写成两个并列`limit`，否则会触发：

`Multiple limits in target effect`

## 七、电网与补给站

- PRC保留双电网与23座固定补给站。
- 其他国家完全跳过电网效果。
- 固定补给站依赖中国州和省份ID，不能通用。
- 通用铁路自动化已经放弃，不得复活v1.1a/v1.1b路线。

## 八、已知历史现象

PRC双电网曾观察到大庆、阿萨姆和新疆部分地区出现原版油田勘探项目。原因未确认，v2.0没有扩大到其他国家。后续若研究，应使用前后存档州块差分，不得凭猜测修改建筑或资源脚本。

## 九、特殊科研项目（v2.1）

实现位于 `common/scripted_effects/PRC_OCS_special_project_effects.txt`（效果）和 `common/decisions/PRC_OCS_decisions.txt` 中五个 `PRC_OCS_complete_*_special_projects` 决议；文件头部注释是权威设计说明。

- 需《Gotterdammerung》DLC（`has_dlc` 检查），沿用 `is_ai = no` 与 `ai_will_do = { factor = 0 }` 约束。
- 按空军（含雷达，9 项）、陆军（9 项）、海军（19 项）、核能（6 项）、火箭（6 项）五类专精各设一个决议，共一键完成 49 个项目。每个项目先 `NOT = { is_special_project_completed = ... }` 判断，再用原版 `complete_special_project` 完成，因此各项目自带的 `project_output`（科技、装备与模块解锁、首枚免费核弹）与正常研究完全一致。
- 项目存在跨专精前置链（如核潜艇需核能树的 `sp_nuclear_engines`，核弹头需火箭树的中程弹道导弹，远程弹道导弹需核弹头）。因此决议可重复执行：某项目因前置未完成被跳过时，完成其他专精后再次点击即可补齐；`available` 为"本专精任一项目未完成"，全部完成后决议自动消失。
- 衍生科技用 `set_technology` 直接授予：包括原版标记 `is_special_project_tech = yes`、需项目完成后另行研究的科技，以及原型迭代奖励中互斥二选一/三选一的隐藏选择科技（海军补给/维修/补给船各方案、离心法同位素分离）。脚本瞬间完成不会触发迭代奖励，因此全部选择项直接授予。
- 脚本完成没有设施州上下文，引擎会跳过 `facility_state_effects`。唯一值得补偿的损失是 `sp_nuclear_reactor` 正常研究时设施州自动获得的 1 级核反应堆——改为在首都 `add_building_construction` 补建。其余迭代奖励（科学家经验、进度加成、挫折事件）本就不应触发，不补偿。
- 每个效果末尾触发 `country_event = { id = PRC_OCS.12 }` 提示事件。

## 十、特殊科研后二阶段编制（v2.2-test1，待验证）

- 仅限 `tag = PRC` 或 `original_tag = PRC`，不进入通用国家分支。
- 精确要求喷火坦克、军用工程车、直升机、洲际轰炸机、空天母舰、轴流式喷气引擎6个相关项目，以及 `tech_trucks`、改进型履带登陆车科技、5项陆军/直升机衍生科技和2项喷气轰炸机科技；不要求完成其余43个项目。
- 新建4个不同名称的二阶段模板，不覆盖旧模板，不自动改编现役师。原版中文 UI 与本地化确认玩家可以手动“退役/复役”模板；但 1.19.2 自带 `effects_documentation.md` 没有模板退役 effect，`retire` 仅适用于角色，`delete_unit_template_and_units` 则明确会同时删除使用该模板的现役师。二进制存档中的退役字段及其安全写法尚未确认，因此脚本不猜字段、不自动退役，也绝不调用该删除 effect。
- “司令部”使用4个 `hq_motorized`、原4个HQ支援连、`ARMY_HQ_TEMPLATE_NAME` 和兵牌 `0/yes`；“装甲师·进化型”为12机械化＋6中自火，团级支援为3个 `mot_fire_support`＋2个 `medium_tank_destroyer_support`；“主力步坦师·进化型”显式使用目标兵牌 `104/yes`。目标存档只对司令部和主力步坦师提供了手调兵牌目标；装甲师与海军陆战队装甲师没有手调目标，保持引擎默认。
- 基础PRC初始化不再创建或发放“43式喷火预备”；二阶段只创建最终 `medium_tank_flame_chassis_3`“中型喷火坦克 III型”。
- 二阶段从 `amphibious_mechanized_equipment_2` 创建四项升级全5的“改进型履带登陆车”，并用 `mark_older_equipment_obsolete` 退役旧设计；存档未给登陆车分配MIO，脚本也不强加。
- 军用工程车项目和衍生科技先生成4个原版父设计；二阶段再分别从版本4、1、2、3派生指挥、突击工程、架桥工程、装甲维修4个同名设计。四项升级均为5，模型与图标分别保留。
