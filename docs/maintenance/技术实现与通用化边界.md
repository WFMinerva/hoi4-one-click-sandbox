## 一、总体架构

v2.0采用“通用核心＋PRC增强层”。脚本文件仍沿用`PRC_OCS_`前缀，这是稳定键名，不代表功能仍仅限PRC。不得为了美观批量重命名这些键，否则可能破坏存档标志、事件和本地化引用。

## 二、国家识别

通用入口面向所有`is_ai = no`国家。PRC增强层使用`tag = PRC`与`original_tag = PRC`识别，确保PRC改国号或形成动态身份后仍保留专属效果，同时避免其他中国国家误获PRC内容。

## 三、科技

科技效果继续使用明确列出的原版科技键，实机效果按用户判断等同控制台`research all`。主要国家科技树外观可能不同，但不另做逐国科技分支。

## 四、装备和模板

- PRC与非PRC分别创建中国名称和中性名称的22个设计。
- 通用设计不得引用PRC专属`design_team`。
- PRC的“主力纯步师”“卫戍部队”“主力步坦师”保留民兵营。
- 非PRC三个对应模板将民兵营全部替换为普通步兵营，共42处。
- 初始化只创建模板，不自动改编现役部队。
- 独立改编决议将全军改成同名“卫戍部队”，模板会按国家分支解析。
- v2.3基础“装甲师”按 `test3.hoi4` 定稿为12个 `mechanized`＋6个 `medium_sp_artillery_brigade`，PRC与通用国家同步；二阶段“装甲师·进化型”也是12＋6，但普通支援连不同，仍为独立模板。

## 五、24师增援

v2.2起改为可重复决议：仅在初始化后显示，选择本国拥有且控制的一个州，一次创建24个同名“主力纯步师”。每个师设置100%人力、装备和初始训练度；完成后等待1天即可再次执行。维护者已在中文环境实机确认连续执行两次、共新增48师，v2.3继续沿用该语义。

## 六、建设作用域

所有通用工业建设（共享槽位、石化、船坞、民用工业）使用`every_owned_state`并在单一`limit`块内检查`is_controlled_by = ROOT`。沿海船坞同时在同一个`limit`块中检查`is_coastal = yes`。禁止重新写成两个并列`limit`，否则会触发：

`Multiple limits in target effect`

### v2.7：占领区基建与补给站加速

- 原版通用建设刻意排除占领区（控制但非拥有的州）。v2.7 新增独立决议 `PRC_OCS_develop_occupied_territory`，以 `every_controlled_state = { limit = { NOT = { is_owned_by = ROOT } } }` 处理**控制但非拥有**的州：基础设施、州防空、空军基地与已有海军基地全部 `instant_build = yes` 秒建。刻意不建工业设施——非核心州工厂产出惩罚使其经济上不划算。
- 新增决议 `PRC_OCS_boost_supply_construction`：`modifier = { production_speed_supply_node_factor = 10 }`，即补给站建造速度 +1000%，持续 365 天。键名与写法直接照抄原版 `restructure_supply_system`（「重建铁路系统」决议，+300%/120天+建3座取消）；本 MOD 版本去掉取消触发器、改为可重复刷新。
- 占领区基建沿用原版建筑 `add_building_construction`，防空科技由决议自动授予（`interwar_antiair`）。
- 红线4同步更新为「工业类建设继续拥有且控制；占领区基建由独立决议处理控制州」，见根目录 `AGENTS.md`。

## 七、电网与补给站

- PRC保留双电网与23座固定补给站。
- 其他国家完全跳过电网效果。
- 固定补给站依赖中国州和省份ID，不能通用。

## 八、已知历史现象

PRC双电网曾观察到大庆、阿萨姆和新疆部分地区出现原版油田勘探项目。原因未确认，v2.0没有扩大到其他国家。后续若研究，应使用前后存档州块差分，不得凭猜测修改建筑或资源脚本。

## 九、特殊科研项目（v2.1）

实现位于 `common/scripted_effects/PRC_OCS_special_project_effects.txt`（效果）和 `common/decisions/PRC_OCS_decisions.txt` 中五个 `PRC_OCS_complete_*_special_projects` 决议；文件头部注释是权威设计说明。

- 需《Gotterdammerung》DLC（`has_dlc` 检查），沿用 `is_ai = no` 与 `ai_will_do = { factor = 0 }` 约束。
- 按空军（含雷达，9 项）、陆军（9 项）、海军（19 项）、核能（6 项）、火箭（6 项）五类专精各设一个决议，共一键完成 49 个项目。每个项目先 `NOT = { is_special_project_completed = ... }` 判断，再用原版 `complete_special_project` 完成，因此各项目自带的 `project_output`（科技、装备与模块解锁、首枚免费核弹）与正常研究完全一致。
- 项目存在跨专精前置链（如核潜艇需核能树的 `sp_nuclear_engines`，核弹头需火箭树的中程弹道导弹，远程弹道导弹需核弹头）。v2.1—v2.2允许重复执行补齐；v2.3改为每类由每个玩家国家执行一次，完成效果直接处理相应项目及衍生科技，执行后以国家标志永久隐藏。
- 衍生科技用 `set_technology` 直接授予：包括原版标记 `is_special_project_tech = yes`、需项目完成后另行研究的科技，以及原型迭代奖励中互斥二选一/三选一的隐藏选择科技（海军补给/维修/补给船各方案、离心法同位素分离）。脚本瞬间完成不会触发迭代奖励，因此全部选择项直接授予。
- 脚本完成没有设施州上下文，引擎会跳过 `facility_state_effects`。唯一值得补偿的损失是 `sp_nuclear_reactor` 正常研究时设施州自动获得的 1 级核反应堆——改为在首都 `add_building_construction` 补建。其余迭代奖励（科学家经验、进度加成、挫折事件）本就不应触发，不补偿。
- 每个效果末尾触发 `country_event = { id = PRC_OCS.12 }` 提示事件。

## 十、特殊科研后二阶段编制（v2.2建立，v2.3通用化）

- v2.2仅限 `tag = PRC` 或 `original_tag = PRC`；v2.3起开放给所有非AI玩家国家。PRC身份保留民兵、师名组和专属兵牌分支，通用国家使用普通步兵与中性设置。
- 精确要求喷火坦克、军用工程车、直升机、洲际轰炸机、空天母舰、轴流式喷气引擎6个相关项目，以及 `tech_trucks`、改进型履带登陆车科技、5项陆军/直升机衍生科技和2项喷气轰炸机科技；不要求完成其余43个项目。
- 新建4个不同名称的二阶段模板，不覆盖旧模板，不自动改编现役师。原版中文 UI 与本地化确认玩家可以手动“退役/复役”模板；但 1.19.2 自带 `effects_documentation.md` 没有模板退役 effect，`retire` 仅适用于角色，`delete_unit_template_and_units` 则明确会同时删除使用该模板的现役师。二进制存档中的退役字段及其安全写法尚未确认，因此脚本不猜字段、不自动退役，也绝不调用该删除 effect。
- “司令部”使用4个 `hq_motorized`、原4个HQ支援连、`ARMY_HQ_TEMPLATE_NAME` 和兵牌 `0/yes`；“装甲师·进化型”为12机械化＋6中自火，团级支援为3个 `mot_fire_support`＋2个 `medium_tank_destroyer_support`；“主力步坦师·进化型”显式使用目标兵牌 `104/yes`。目标存档只对司令部和主力步坦师提供了手调兵牌目标；装甲师与海军陆战队装甲师没有手调目标，保持引擎默认。
- 基础PRC初始化不再创建或发放“43式喷火预备”；二阶段只创建最终 `medium_tank_flame_chassis_3`“中型喷火坦克 III型”。
- 二阶段从 `amphibious_mechanized_equipment_2` 创建四项升级全5的“改进型履带登陆车”，并用 `mark_older_equipment_obsolete` 退役旧设计；存档未给登陆车分配MIO，脚本也不强加。
- 军用工程车项目和衍生科技先生成4个原版父设计；二阶段再分别从版本4、1、2、3派生指挥、突击工程、架桥工程、装甲维修4个同名设计。四项升级均为5，模型与图标分别保留。
- 空天母舰、洲际轰炸机、喷气式战略轰炸机I型、喷气式战术轰炸机II型各创建四项升级全5的新设计并退役旧版本。若当前国家拥有 `PRC_peoples_aviation_company_of_china_organization`，通过 `design_team = mio:...` 自动应用存档所示12特质MIO；没有该MIO的PRC后继身份走无MIO后备分支。
- 决议通过 `PRC_OCS_special_project_forces_evolved` 保证一次性；效果内部再次检查该标志，防止重复脚本调用。
- 8个原版模板不自动删除或退役；如需隐藏，当前只能由玩家在 UI 中手动退役。自动化必须等到可调用 effect 或存档字段得到可复现实验证据后再评估。

### 通用MIO生成表

- `tools/generate_universal_mio_effect.py`读取原版组织定义，展开 `include`、`add_trait`、`override_trait` 与 `remove_trait`。
- test7—test10实机已点集合优先；未采样公司选择确定性的最大合法互斥集合并按父节点拓扑排序。
- 生成文件为 `common/scripted_effects/PRC_OCS_shared_mio_effects.txt`，覆盖444家公司、4945项目标特质；不得手工编辑，使用 `--check`验证重建一致性。
- 每家公司先确认当前国家实际拥有，再直接进入相应 `mio:`作用域；不存在的公司跳过。PRC原有4家专属组织不重复生成。
- 不额外增加MIO资金或等级。MIO方针与特质不是同一机制，现有公开脚本效果无法为指定MIO自动选择方针。

### 每国一次与切换国家

- 初始化、统一改编、进化编制和五类特殊科研显式设置 `fire_only_once = no`，再由国家完成标志控制每国一次。
- 决议完成标志保留在 `visible` 的 `NOT` 中：当前国家执行前可见，完成后消失。
- 分类必须使用 `allowed = { always = yes }` 在开局为所有国家实例化；分类/决议 `visible`、决议 `available` 中的 `is_ai = no` 及 `ai_will_do = 0` 继续禁止AI使用。
- 维护者已于2026-07-31实机确认同局切换至开局由AI控制的国家后，分类按预期出现并可初始化。
