# 黄金存档制度

> 生效：2026-08-19（A 立项「实机监测机制」步骤2 交付，门二结论 3：哈希入仓、二进制不入 git）。
> 定位：把历史上非正式的 test1–test5.hoi4 测试档升格为「黄金存档」制度——固定复现路径的输入侧，保证每轮实测起点一致、可追溯。

## 一、登记规则

1. 每个黄金存档必须登记：用途、游戏版本（`code_revisions.log` 的 game_hash_short）、MOD 版本线、创建日期、SHA-256、本机归档位置（单位机 `%USERPROFILE%\Documents\Paradox Interactive\Hearts of Iron IV\save games\`）。
2. 哈希入仓：登记表在本文件下方；二进制 `.hoi4` 不入 git（50 MB 级），只留本机 `save games\` 与脱敏副本目录。
3. 黄金存档一旦被实测轮次修改，需另存新档（如 `test1` → `test1a`），不得覆盖原档；原档哈希保持不变。

## 二、使用规则

1. 每轮实机回归从黄金存档加载，按固定 console 指令序列操作：控制台执行 `effect PRC PRC_OCS_selftest_run_suite`（或 `event PRC_OCS_selftest.1 PRC`；亦可先 `tag PRC` 切国再执行 `effect PRC_OCS_selftest_run_suite`）→ 点验项 → 存判定档。命令口径与 `common/scripted_effects/PRC_OCS_selftest_effects.txt` 文件头注释一致。
2. 判定档（实测后存档）不升级为黄金存档；仅当功能基线发生版本化变化时，由机主拍板重建黄金存档并更新登记。
3. 游戏版本升级导致旧黄金存档不可载时，视为「游戏版本升级复合风险」（立项文档 6.3 风险 8）：重建基线存档并复跑步骤0 能力实测。
