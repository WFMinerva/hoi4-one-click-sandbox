# v2.9 QQ 交流群反馈整理与评估（2026-08-23）

> 来源边界：本记录依据维护者在对话中粘贴的 2026-08-23 22:50–23:34 QQ 群聊文本。群聊观点属于玩家反馈，不自动等于已复现缺陷；现行状态以 v2.9 源码、发布文档和已有实机证据为准。本记录只分级，不授权实现。

## 一、已由当前源码确认

1. **宣战理由与特殊规则已经拆开**：v2.9 当前存在独立 `PRC_OCS_create_wargoals`，`PRC_OCS_unlock_special_rules_effect` 不再附带战争借口。玩家所说“合并进规则直接炸了”是 test5→test6 开发过程中的真实问题，但不是当前正式源码仍未修的缺陷。
2. **意识形态支持率与切换国体已经拆开**：当前事件菜单分别提供 `add_popularity` 与 `set_politics`，没有把“拉满支持率”强制绑定“直接改国体”。玩家对国策流程被跳过的担忧成立，但现行实现已按该原则拆分。
3. **顾问需求曾被误译**：原反馈意图是简化将领练级后转任专家顾问的过程；原版未找到安全的“将领转顾问”脚本接口，开发过程一度扩为大量 PRC 顾问自动上任。当前正式实现已收束为适配硬编码槽位的 10 人，但它仍是“自动任命既有顾问”，并不等于玩家原始设想的“把练成的将领转职”。
4. **AI 参与痕迹并非纯主观印象**：碉堡/要塞群概念混淆、宣战理由与规则错误合并、顾问需求误译、工坊简介擅自改写，均有本仓修改记录或本轮发布事实支持。速度提升是真实收益，但语义偏移也是已发生的成本。

## 二、高优先级待审计

### P1：特殊科研互斥选择是否被预先叠加

- 玩家原始目标是模拟正常特殊科研流程，让玩家逐项选择 A/B/C 研发侧，而不是一次获得全部互斥效果。
- 当前 `docs/maintenance/技术实现与通用化边界.md` 与 `PRC_OCS_special_project_effects.txt` 明确记录：瞬间完成不触发迭代奖励，因此直接 `set_technology` 授予部分原型迭代的互斥隐藏选择科技，海军支援/维修/补给方案与离心法同位素分离等存在“全部授予”设计。
- v2.6 之后虽然加入逐项选择事件，但“存在选择 UI”不能证明相关隐藏科技在菜单前没有全部获得，也不能证明相反修正不会同时叠加。玩家举出的“同时降低航程和增加航程”属于合理风险假设，尚未用前后存档或最终 modifier 证明。
- 判定：不是已证实的存档损坏，也不是可忽略误解；是与原始产品意图冲突的长期语义债。下轮第一项应做原版奖励—直接授予科技—选择事件效果三表对账，再决定移除哪些预授予项。

## 三、界面精简建议的原则

- 民用工厂、军用工厂、船厂可以放入同一入口事件，但内部仍应保持三个独立效果；它们的前置、沿海条件、槽位和重复执行语义不同，不能简单合并成一个不可分割效果。
- 建筑类可以使用“总入口＋逐项菜单”，但电网、要塞、大型设施、工业和占领区开发的作用域、DLC 门禁与回滚条件不同，不应为减少按钮数量而共享完成标志。
- 间谍机构“创建机构”和“升级部门”分开并非没有理由：后者依赖机构已存在。可用一个入口菜单改善观感，但必须保留顺序与失败提示。
- 年份科技改事件菜单是合理的界面压缩候选；必须保持每个年份独立可选，不能回滚成“全部年份一次获得”。
- 总原则：**合并入口，不合并语义；共享菜单，不共享完成标志。**

## 四、新功能与传播建议分级

### 可进入后续调研

- MOD 首次加载宣传事件：介绍功能、作者、反馈渠道。涉及群号或二维码时先确认隐私、长期有效性和图片版权；不得强制每次开局弹出，可设置一次性或关闭选项。
- 全球武器市场准入：玩家给出第三方视频线索，但“所有国家互加隐藏修正”的实现、性能、AI 行为和版本兼容尚未核验；先调研原版市场准入触发器与开源实现，不直接照抄。
- 反向殖民控制：增加抵抗、降低顺从，用于触发起义。应独立于现有“顺从 100/抵抗 0”决议，并明确只处理占领州，防止再次对无 resistance 州刷错。
- 一键海军：属于另一 MOD 的功能合并建议，需要先审计其实际用途、代码质量和与本 MOD 定位的重叠；“二手船没感觉”说明不能仅机械搬入。
- AI 沙盒导演：为 AI 国家设置科技、装备和 buff 后观战，是比“开局省操作”更宽的产品方向，可作为独立工作流调研，不能悄悄扩进现有初始化按钮。

### 暂不建议立即执行

- 立即联系 B 站 UP 主联合投稿。当前 v2.9 统一实机清单并未逐项留证，特殊科研互斥语义又出现高价值疑点；此时扩大曝光会同时放大维护负荷，与维护者工作日无暇处理相冲突。
- 建议先满足三个传播门槛：特殊科研对账完成；一轮覆盖核心入口的正式回归留档；形成固定反馈模板与“周末统一处理”的响应边界。满足后再做教程向宣传比立即广撒网更稳。

## 五、对下轮工作的建议顺序

1. 审计特殊科研互斥科技与逐项选择事件，输出三表对账，不先改代码。
2. 将群聊中的历史缺陷与现行缺陷分开，避免重复修复已解决项。
3. 设计“总入口＋独立子效果”的 UI 精简方案，先做线框和状态机，不直接合并脚本。
4. 再调研市场准入、反向抵抗、宣传事件和一键海军。
5. 完成稳定性门槛后再决定是否联系 UP 主宣传。
