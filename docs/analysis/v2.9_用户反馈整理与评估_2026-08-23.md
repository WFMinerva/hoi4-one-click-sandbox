## 一、已核实缺陷（源码定位＋日志实锤）

### D1. C1 附庸侧「overlord」无效事件目标（日志实锤 ×3，对应 B5）

- **现象**：玩家 B5「提升自身自治等级失败，只获得了800自治点数，且重复点无效」。
- **日志**：`error.log` ×3 `common/scripted_effects/PRC_OCS_political_effects.txt:17: overlord: invalid event target: overlord`（16:06:32 会话）。
- **根因**：`PRC_OCS_adjust_subject_autonomy_effect` 的附庸分支直接写 `overlord = { … }`；1.19 脚本效果中 `overlord` 不是合法事件目标（官方 effects 文档无此作用域）。该块整体失败→自身上调自治未生效；「800 自治点数」疑为失败块的半执行残留或界面读数，待修复后复测确认。
- **修法**（调研结论）：反向作用域链——`every_country = { limit = { ROOT = { is_subject_of = PREV } } set_autonomy = { target = ROOT autonomy_state = autonomy_collaboration_government freedom_level = 0.9 } }`（`is_subject_of` 为合法 trigger，修复1 已用）。附庸方（宗主降附庸）维持现状（玩家 B4 确认「调整附庸正常」）。
- **附加（B4）**：玩家要求「减少自治度点数，使附庸界面合并操作可用」——现 `freedom_level = 0.1` 可能不满足 UI 合并（整合）按钮的精确阈值；候选：`freedom_level = 0` 或 `add_autonomy_score = { value = -100 }`（官方 effect，BBA_Italy/BFTB_Bulgaria 有先例），实机验证 UI「整合」按钮点亮。**且不引入脚本化 annex**（玩家明确：annex 会丢指挥官/军队/舰队；目标是让原版 UI 合并可用）。

### D2. C3 顺从度「add_compliance 无抵抗」刷错（日志实锤 ×190）

- **现象**：玩家未点名（可能未注意），日志实锤——`add_compliance <州名> does not have resistance` ×190（`PRC_OCS_political_effects.txt:37`，16:06:32 与 16:26:42 两次点击各一批）。
- **根因**：`PRC_OCS_max_compliance_effect` 对 `every_controlled_state` 无条件 `add_compliance = 100`＋`set_resistance = 0`；非占领/非抵抗州（本土、殖民地非占领区）无 resistance 属性→每州一条错误。
- **修法**：仅对存在抵抗/顺从语义的州执行——加 `limit = { is_occupied = yes }`（或等价守卫，对照原版先例），并保留 `set_resistance = 0`；error.log 须恢复 0 字节级洁净。

### D3. 工厂类决议在「铺满后手动拆除留空位」的州失效（A5）

- **现象**：A5「一键民工军工船厂三个功能，在拥有『铺满工厂但手动拆除工厂后留有空位』的地块时，功能失效」。
- **根因**：`PRC_OCS_refresh_industrial_priority_flags_effect`（construction_effects.txt:21-42）只**置位**完成 flag（`industrial_complex > 19` → `set_state_flag = PRC_OCS_civilian_industry_queued` 等），**拆除后永不清除**；三个工厂决议（民用/军工/船厂）的 `if` 块以 `NOT = { has_state_flag = … }` 跳过该州→空位永不补建。
- **修法**：refresh 效果补 `else = { clr_state_flag = … }` 三处（industrial_complex/arms_factory/dockyard 各自 <20 时清位）；顺带核对 `refresh` 在三个决议内的调用时机（现为决议效果入口调用，OK）。

### D4. 特种部队子学说仅「密集空投」生效（A1）

- **现象**：A1「特种部队仅有密集空投（paratroopers_2），第二个格子是锁着的」。
- **源码**：`PRC_OCS_configure_doctrines_effect` 依次 `set_sub_doctrine = marines_2 / mountaineers_2 / paratroopers_2`（research_effects.txt:396-398）；玩家实机仅最后一个（paratroopers_2）生效。
- **根因候选**（待实机/深调研定案，工程检查不能代替实机）：
  1. 引擎特种部队子学说单槽互斥（最后写入胜出）——与步兵/作战分支多选并存（机主 test1 已见 commandos＋infiltration 同显）机制不同；
  2. `available` 门控：marines_2 需 `has_tech = marines`、paratroopers_2 需 `has_tech = paratroopers`、mountaineers_2 需 `has_tech = tech_mountaineers`——research_all **缺 `marines`/`paratroopers` 两个基础科技键**（tech_mountaineers/rangers_tech/tech_special_forces 已含）；但观察方向与门控推论相反（未授科技者反生效），仅作候选；
  3. DLC 可见性（AAT `visible`）或 UI 显示路径。
- **修法候选**：①补 `marines`/`paratroopers` 科技键后逐一实机验证三分支并存；②若引擎单槽，改为事件菜单单选一个特种部队子学说；③实机确认后按引擎结论定。**需机主拍板**（见第四节第 1 条）。

### D5. 意识形态切换缺失（A9）

- **现象**：A9「没有实装立刻切换国体的效果，只是增加了支持度；增加支持度和切换为该国体应分为单独的事件选项，不然会卡国策」。
- **根因**：修复1 因 `set_ideology` 无此 effect（官方 effects 文档确认无）删除了切换；现事件 86/87 仅 `add_popularity = { ideology = X popularity = 1.0 }` 拉支持度（引擎支持度总和恒 100，仅单项生效）。
- **官方现成方案（调研确认）**：`set_politics = { ruling_party = <民主/法西斯/共产/中立> }`——1.19.2 effects 文档收录，AAT_Denmark 事件（`events/AAT_Denmark.txt:1428-1446`）有 `set_politics = { ruling_party = democratic/neutrality/communism/fascism }` 完整先例。
- **修法**：事件菜单按玩家要求拆分——每个意识形态「拉满支持度」与「切换为国体」为独立选项（候选布局见第四节第 8 条）；切换选项 `set_politics`；契约加「永不回归 set_ideology」守卫（现有守卫保持）。

### D6. 核反应堆与民用核反应堆冲突（A7）

- **现象**：A7「核反应堆和民用反应堆冲突，实际只建成核反应堆。个人觉得民反更有用，全铺满也够生产核弹了」。
- **源码**：`PRC_OCS_queue_major_structures_effect`（construction_effects.txt:1041-1054）对每州分别 `add_building_construction` 核反应堆与民用核反应堆（各 `level = 1`，州上限 1）；两建筑同州互斥/后者被前者覆盖→只建成核反应堆。
- **修法候选**：①州内二选一（玩家倾向民用核反应堆）；②按首都/特定州分工；③队列分开州。**需机主拍板**（第四节第 2 条）。

### D7. 史前科技进入一键全科技与年份按钮（A1/A11）

- **现象**：A1「科技出现大量无dlc史前科技：一战坦克、轻型坦克一型/二型/三型、基础型/改进型两栖坦克、轻型自行防空炮二型、中型坦克一型、重型坦克一型/二型、战间期战斗机、战斗机一型、舰载战斗机二型、海军轰炸机一/二/三型、自杀攻击用飞行器」；A11「全部科技都有研发了史前科技的问题」。
- **根因**（本机原版 1.19.2 实文件核对）：上述键全部**真实存在于原版科技文件**（armor.txt/air_techs.txt/MTG_naval.txt 等），属 NSB/MtG/BBA 改版前的**隐藏遗留科技**（不在科技树中显示）；v2.9-test5 C8 补全（284→369）从国策/事件奖励键提取时把这些遗留键一并纳入 `PRC_OCS_research_all_effect`（如 `gwtank`/`fighter1`/`naval_bomber1-3`/`cv_fighter2`/`basic_light_tank`/`early_fighter`/`basic_submarine`/`advanced_light_tank`/`amphibious_tank(_2)`/`improved_light_tank`/`improved_heavy_tank`/`improved_light_spaa`/`pre_dreadnoughts`/`suicide_craft`/`suicide_charge`/`transport` 等）；其中带 `start_year` 者（fighter1=1936、naval_bomber1=1936、cv_fighter2=1940 等）同时进入年份按钮→一键后研发历史出现大量史前科技。
- **修法候选**：①**原版存在性过滤**：以本机原版科技文件为基准校验每个键的「树内可见性」（隐藏遗留键无 `path`/不可达——需工具化判定，工作量较大）；②**显式排除清单**：维护遗留键黑名单（上列约 17–20 键）＋契约断言（research_all/年份组不得含黑名单键，未来键漂移自动报警）。**需机主拍板**（第四节第 4 条）。

### D8. 年份按钮缺口（A11）

- **现象**：A11「36年科技缺失：巡洋舰重点防护装甲方案、消防演练、染色弹、无线电、机械计算机、初级火控系统、密集工业、分散工业、挖掘技术一；38年缺改进型火控系统；39年缺先进型火控系统」。
- **根因**（本机原版核对）：上述键在原版**均无 `start_year`**（`radio`/`mechanical_computing`/`basic|improved|advanced_fire_control_system`/`damage_control_1`/`excavation1`/`concentrated_industry`/`dispersed_industry`/`improved_heavy_armor_scheme` 等），F17 生成器（`tools/generate_year_tech_effects.py`）按 `start_year` 分组、无年份键跳过（仅 research_all 覆盖）→年份按钮缺失。另 A11「不研发需要特殊研究才能点的科技」：喷气/核能等特殊科研派生科技由「完成特殊科研」决议链授予（B3 既有设计），一键全科技不含 `sp_*`/喷气键——需逐键核对覆盖路径后决定是否纳入一键全科技（调研项）。
- **修法候选**：①无 `start_year` 键全部并入「1936及以前」组（简单、符合玩家直觉——这些均为早期基础科技）；②按依赖/名称启发式分年（工作量大）；③保持现状仅文档说明。**需机主拍板**（第四节第 5 条）。

### D9. 预设设计覆盖缺口（A3）

- **现象**：A3「舰载战斗机、舰载支援机、重型战斗机、战术轰炸机编制丢失。海军舰船设计全部没有」。
- **根因**：`PRC_OCS_create_variants_effect`（equipment_effects.txt，30 个类型）覆盖＝陆战装备＋少量空（海军轰炸机三型、大型巡逻机、侦察机、CAS、洲际轰炸机、直升机、母舰机、喷气轰炸机）——**无任何战斗机变体**（战斗机/舰载战斗机/舰载支援机/重型战斗机/战术轰炸机），**无任何海军舰船变体**（无 `ship_hull_*`）。

### D10. 潜艇 MIO 两特质未点（B3）

- **现象**：B3「福克无异常。霍瓦慈改线正常，但改进型鱼雷雷管、简化型耐压船体设计未点」。
- **根因**（本机原版 00_generic_organization.txt 核对）：
  - `generic_mio_trait_improved_torpedo_detonators`（改进型鱼雷雷管）：`any_parent = { highly_efficient_diesel_electric_propulsion_systems | open_cycle_propulsion }`——可从**隐蔽侧**（highly_efficient）到达；但 D12 分类（`generate_universal_mio_effect.py` SUBMARINE_TORPEDO_TRAITS）把它整侧丢弃；
  - `generic_mio_trait_simplified_pressure_hull_design`（简化型耐压船体设计）：`all_parents = { experimental_anechoic_tiles | improved_torpedo_detonators }`——需隐蔽侧 anechoic＋improved_torpedo 双前置；后者被丢弃后不可达。

### D11. 电网链实际不触发＋文案晦涩（B4）

- **现象**：B4「不理解『电网可建，通用化』的含义。两种电网可以正常建设，没有一键建成，也没有加速」。
- **根因**：D2 通用化后的电网链（construction_effects.txt:442-509）触发条件苛刻——需州炼油/燃料库目标完成＋民用工业满 20 flag＋油资源分支判断＋`power_grid_queued` flag；玩家常规流程几乎不满足→决议实际不建电网；决议 desc（`PRC_OCS.3.d`）仅说明「满足工业建设优先条件的地区还将建设双轨制国家电网」，按钮文案无「电网可建，通用化」字样（该句出自文档/交接，玩家理解为按钮文案——文案需重写）。
- **修法候选**：①电网拆独立决议（无条件一键建电网，energy/industrial 按州资源分支）；②放宽条件并入现有决议；③加速覆盖电网（见 F3）。**需机主拍板**（第四节第 7 条）。

### D12. 好感数值 200 不够（B4）

- **现象**：B4「改善国家关系正常，但数值太低。正常游玩时仍要进行额外操作，是否改为一千好感」。
- **根因**：`cheat_opinion_modifier_good` 原版 value=200（00_opinion_modifiers.txt 实测）。
- **修法**：自定义 opinion modifier（`PRC_OCS_opinion_good`，value=1000，时长 3650 天或永久）替换；200→1000 的数值上限以实机为准（200 已可用→1000 大概率合法）。

## 二、功能调整（玩家点名）

### F1. 库存与设计顺序（A2）

- **现象**：A2「获得大量装备库存正常。但为什么会在没有创建装备设计前就获得大量装备，怀疑这些装备都是史前科技。该功能应设计在创建装备设计之后并调用新的装备获得库存」。
- **核对**：库存 73 键全部为现代装备（无遗留键）——玩家「史前科技」疑为误判（实为无设计可用）；但顺序问题属实：库存按钮独立于设计按钮。
- **修法**：库存效果改为「先创建预设设计（调用设计效果），再按新设计装备集授予库存」——或库存决议 `available` 要求 `PRC_OCS_preset_designs_created` flag（先设计后库存）；PRC/generic 双分支同步。**需机主拍板**（第四节第 9 条：联动 vs 前置）。

### F2. 战争借口独立按钮＋语义澄清（B4）

- **现象**：B4「获得战争借口正常，但是这个功能不能被合并进任何功能按键里，应单独按键。我当时对这部分规则的实际含义是，使外交界面的『正当化战争目标』按钮可用」。
- **现状**：`PRC_OCS_unlock_special_rules_effect` 把 8 条 `set_rule`＋对全部国家 `create_wargoal annex_everything` 合并在一键内（desc 明示）。
- **修法**：`create_wargoal` 拆出独立决议「制造战争借口」（或并入单独按钮）；「使外交界面正当化按钮可用」的脚本化途径需轻调研（game rule 不可脚本改；查 justify 按钮前置机制——候选 `set_rule` 规则键是否含 justification 类、或外交按钮可用性由 tension/rule 决定）。**需机主拍板**（第四节第 6 条）。

### F3. 加速强度与覆盖（A6）

- **现象**：A6「无异常，但建造速度不够快，且覆盖范围不足」。
